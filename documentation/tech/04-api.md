## 1. Принципи (💡)

- **Сервер — єдине джерело правди.** Клієнт надсилає **команди** (наміри), сервер перевіряє і виконує.
- Два канали:
  - **HTTPS (REST/JSON)** — команди і запити стану;
  - **WebSocket через SignalR** — події від сервера (бій, атака, таймери). 💡 Бінарний формат MessagePack: у 2–3 рази компактніше за JSON (економія трафіку на мобільному, документ 02, розділ 5).
- **Версія API** у шляху (`/api/v1/...`), щоб майбутні клієнти (ПК, мобільні) не ламалися після оновлень.
- Усі часи — **UTC**, у форматі ISO 8601; клієнт показує в часовому поясі гравця.

## 2. Авторизація (💡)

- ✅ На старті: вхід через **email + пароль** і **Google**; підтвердження email при реєстрації (💡). Apple (обов'язковий для App Store) і Discord додаємо пізніше.
- Токен сесії (короткий) + токен оновлення (довгий). 💡 Реалізація на ASP.NET Core Identity (документ 02).
- Один акаунт — один гравець у всесвіті (✅ всесвіт один).

## 3. Команди (💡 приклади)

| Метод | Шлях | Що робить |
|---|---|---|
| POST | `/api/v1/planets/{id}/buildings` | Поставити будівлю в чергу |
| POST | `/api/v1/planets/{id}/production` | Поставити у виробництво (ресурси, деталі) |
| POST | `/api/v1/designs` | Зберегти проєкт корабля |
| POST | `/api/v1/shipyard/{planetId}/build` | Збудувати кораблі за проєктом |
| POST | `/api/v1/fleets/{id}/orders` | Наказ флоту: переліт, атака, видобуток, ескорт, повернення |
| POST | `/api/v1/battles/{id}/orders` | Накази на наступний цикл бою |
| POST | `/api/v1/research` | Почати дослідження |
| POST | `/api/v1/market/orders` | Виставити лот |
| POST | `/api/v1/market/orders/{id}/buy` | Купити лот (доставка конвоєм чи порталом) |
| POST | `/api/v1/exchange` | Обмін кредитів і торгової валюти |
| POST | `/api/v1/clans/{id}/diplomacy` | Запропонувати стосунки |

Кожна команда має **ідентифікатор запиту** (idempotency key): повторне надсилання (наприклад, через збій мережі) не виконає дію двічі.

## 4. Запити стану (💡)

| Метод | Шлях | Що повертає |
|---|---|---|
| GET | `/api/v1/me` | Гравець, ресурси, тривоги |
| GET | `/api/v1/planets/{id}` | Планета, будівлі, черги, ресурси (з часом `t` і швидкостями) |
| GET | `/api/v1/map/sector/{id}` | Об'єкти сектора в межах огляду (✅ туман війни) |
| GET | `/api/v1/fleets` | Флоти і їхні маршрути |
| GET | `/api/v1/battles/{id}` | Стан бою, поточний цикл |
| GET | `/api/v1/reports` | Звіти |

💡 Ресурси сервер віддає як «кількість + швидкість + час», а клієнт сам анімує лічильник, не питаючи сервер щосекунди.

## 5. Події WebSocket (💡)

| Подія | Коли |
|---|---|
| `incoming_attack` | Радар помітив ворожий флот |
| `battle_started`, `battle_cycle`, `battle_ended` | Бій |
| `queue_done` | Будівля, дослідження, виробництво готові |
| `fleet_arrived` | Флот прибув |
| `market_sold`, `convoy_intercepted` | Ринок |
| `chat_message`, `mail` | Повідомлення |
| `newbie_protection_ending` | Захист новачка закінчується |

💡 **Номери подій.** Кожна подія для гравця має зростаючий номер (`seq`). Після обриву клієнт надсилає номер останньої отриманої події, і сервер повертає лише пропущені (документ 01, розділ 3.5). Якщо пропусків забагато, клієнт запитує свіжий стан через HTTPS.
💡 Повідомлення містять лише зміни (дельти); клієнт підписується тільки на те, що бачить (свою планету, свій бій, видимий сектор).

## 6. Адмінські команди (💡)

- Окремий розділ `/api/admin/...`, доступний лише акаунтам адмінів з ролями (документ 05, розділ 8).
- Приклади: правка балансу, перегляд і заморожування акаунтів, розгляд скарг, перегляд журналу дій.
- Кожна адмінська команда записується в журнал (хто, що, коли, старе й нове значення).
- Інтерфейс: власна сторінка в тому самому застосунку (✅ документ 02).

## 7. Публічний API (✅ лише читання; деталі 💡)

✅ Публічний API існує **лише для читання** (калькулятори, карти, трекери кланів, симулятори). Дій через нього виконати не можна.
- 💡 Не на старті: спершу тільки власний API для клієнта; публічний режим додаємо після запуску, коли з'явиться попит.
- 💡 Окремі ключі доступу гравця, відкликання ключа, власні ліміти запитів, окремий пул ресурсів сервера (щоб не заважав грі).
- 💡 Віддає лише те, що гравець і так бачить у грі (✅ туман війни), без чужих прихованих даних.
- Команди (діють) і запити (читають) розділені в API ще з документа 04, розділи 3–4, тому публічний режим не потребує переробки.
- Автоматизація дій (боти) заборонена правилами гри; детально в документі 05, розділ 4.
