## 2. Критерії вибору серверного фреймворку (✅ від автора)

1. Швидкість (продуктивність, пам'ять, багатопоточність).
2. Безпека «з коробки» (вхід, ролі, захист від типових атак).
3. Модульність (ядро, яке розширюють).
4. Якісні бібліотеки (база даних, реальний час, фонові задачі, тести).

## 3. Сервер (✅ C# + ASP.NET Core і PostgreSQL підтверджено; решта 💡)

| Частина | 💡 Технологія | Чому |
|---|---|---|
| Мова і каркас | **C# + ASP.NET Core** (.NET LTS) | Швидкий, багатопоточний, повний каркас; сувора типізація допомагає агентам |
| Вхід і ролі | ASP.NET Core Identity, вбудоване обмеження частоти запитів | Безпека без власних велосипедів |
| Реальний час | **SignalR** (бінарний формат MessagePack) | WebSocket із групами; у 2–3 рази компактніше за JSON |
| Фонові служби | BackgroundService / Hosted Services | Планувальник подій, ігровий рушій, обробник боїв |
| База даних | **PostgreSQL** + EF Core (міграції) + Dapper для гарячих запитів | Транзакції для економіки, складні запити, JSONB |
| Кеш і черги | Redis — лише за потреби | Етап 1 без нього: гарячий стан у пам'яті сервера |
| Модульність | Модульний моноліт: проєкт на модуль (економіка, флот, бій, ринок, клани) | Ядро розширюється; модуль можна винести пізніше |
| Тести | xUnit + симулятори балансу на тому самому коді | Економіка й бій перевіряються автоматично |
| Контракт API | OpenAPI → автогенерація TypeScript-типів | Клієнт і сервер не розходяться |

**Чому PostgreSQL:** грабунок, торгівля й оплата мають змінювати кілька записів разом (транзакції); потрібні складні запити (ринок, рейтинг, клани); JSONB для звітів і наказів. MySQL слабший по JSON і складних запитах, MongoDB гірший з транзакціями, SQLite не підходить для багатьох одночасних записів.

### Запасні варіанти сервера
| Варіант | Сильні сторони | Слабкі сторони |
|---|---|---|
| TypeScript + NestJS | Одна мова з клієнтом, модульність | Один потік на процес: бої потребують окремих процесів |
| Elixir + Phoenix | Найкращий реальний час | Нішева мова, мало бібліотек |
| Kotlin + Spring Boot | Дуже повний, безпека | Важчий, повільніший старт |
| Go (Gin/Echo; Goravel) | Найвища швидкість, дешеві сервери | Немає зрілого повного фреймворку; каркас і безпеку збирати вручну |
| Rust (Axum, Loco) | Максимальна швидкість | Найповільніша розробка |

## 5. Трафік і повільний інтернет (💡)

1. **Ассети лише через CDN** (наприклад, Cloudflare R2: без плати за вихідний трафік). Ігровий сервер ассети не віддає.
2. **Кеш:** файли з версією в імені качаються один раз (service worker).
3. **Стиснення:** WebP/AVIF для картинок, Opus для звуку, спрайт-атласи. Великі відео обмежуємо; ефекти робимо анімаціями в грі.
4. **Бюджет першого завантаження:** до 2–3 МБ до першого екрана; бої, музика, інші раси підвантажуються пізніше.
5. **Режим економії** вмикається автоматично на повільній мережі: менше ефектів, без відео, рідші оновлення карти.
6. **Легкі дані:** бінарні повідомлення, дельти замість повного стану, номери подій: після обриву клієнт докачує лише пропущене (документ 01, розділ 3.5).
7. **Бій:** клієнт отримує звіт циклу (кілька КБ) і анімує локально.
