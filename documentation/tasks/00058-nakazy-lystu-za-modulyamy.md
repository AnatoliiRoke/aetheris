# Задача 00058 — Накази польотного листа за модулями флоту

> **Статус:** ✅ виконано (11.11.2026)
> **Запит автора (11.11.2026):** сховати накази, якщо немає відповідного модуля: «Гіперперліт» без Гіпердвигуна, «Стрибок» без Джамп-двигуна, «Сканування» без Астросканера й Корабельного радара.
> **Пов'язані:** [00050](00050-politnyi-lyst-flotu.md), [00057](00057-zavantazhennia-ta-vyvantazhennia-v-politnomu-lysti.md).

## 1. Рішення

1. Модуль, що відкриває наказ, позначений **даними**: атрибут деталі `flight_order` зі значенням `hyperfly`, `jump` чи `scan`. Клієнт не знає жодного модуля за назвою чи кодом.
2. У сіді позначені: Гіпердвигун (`hyperfly`), Джамп-двигун (`jump`), Астросканер і Корабельний радар (`scan`). Атрибут редагується в адмінці в списку «Деталі» (поле «Відкриває наказ листа»).
3. Каталог кораблів віддає модулю `flightOrder`; діалог листа пропонує наказ лише флоту, в якому є корабель із таким модулем. Наказ, що вже є в листі, лишається в списку.

## 2. Критерії приймання

1. Флот без Гіпердвигуна не має «Гіперперельоту» у списку наказів; без Джамп-двигуна немає «Стрибка»; без Астросканера чи Радара немає «Сканування».
2. Атрибут можна задати модулю в адмінці без зміни коду.
3. `dotnet build -c Release`, `npx tsc --noEmit`, `npm run build` чисті.

## 3. Результат виконання (11.11.2026)

- Сервер: ключ атрибута `flight_order` і коди `PartFlightOrders` (`ProductionCodes.cs`), варіанти й тексти в адмінці, поле `FlightOrder` у `ShipModuleDto` і в каталозі.
- Дані: сід `production-reference-seed.json` і база `aetheris_dev` (4 рядки в `part_attribute`).
- Клієнт: `flightOrder` у типі модуля, `fleetOpenedOrders` у `fleetExtraction.ts`, фільтр типів у `FlightPlanDialog.tsx`.
- Команди: збірка Host (Release), `npx tsc --noEmit`, `npm run build` без помилок. Тести не запускались; живий прогін у Chrome в `00058-pytannia.md`.
