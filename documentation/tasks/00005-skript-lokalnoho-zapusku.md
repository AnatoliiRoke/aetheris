# Задача 00005 — Скрипт локального запуску (сервер + клієнт однією командою)

> **Статус:** ВИКОНАНА 26.10.2026 (створено 25.10.2026); результат у розділі «Результат виконання». Маленька задача, виконується після 00001.
> **Документи:** [00001](00001-zibraty-stek-i-zapustyty-server.md), [tech/02 Стек](../tech/02-tekhnolohichnyi-stek.md)

## 1. Мета
Під час розробки потрібні два процеси: сервер (C#) і сервер клієнта Vite. Автор хоче запускати їх **однією командою**. Docker не використовуємо до релізу v0.1 (✅ автор, 25.10.2026).

## 2. Що входить
- Скрипт `dev.sh` у корені (macOS/zsh): перевіряє наявність .NET SDK (шукає також у `~/.dotnet` і додає в PATH лише для процесу), Node, доступність PostgreSQL і наявність рядка підключення (без виведення пароля); запускає сервер і клієнт одночасно, префіксує логи (`[server]`, `[client]`), при Ctrl+C зупиняє обидва процеси.
- Зрозумілі повідомлення про помилки українською (немає .NET, база недоступна, порт зайнятий).
- Розділ у README «Швидкий старт: одна команда».

## 3. Критерії приймання
1. `./dev.sh` піднімає сервер і клієнт, у браузері відкривається http://localhost:5173 з працюючим API.
2. Ctrl+C зупиняє обидва процеси, порти вільні.
3. Скрипт не виводить паролі й не змінює глобальні налаштування терміналу.
4. Якщо чогось не вистачає, скрипт називає, чого саме, і як виправити.

## 4. Що не входить
Docker, production-режим (віддача зібраного клієнта сервером робиться перед релізом v0.1 разом з Docker), Windows/Linux.

## Результат виконання (26.10.2026)

### Що зроблено
- `dev.sh` у корені (zsh, macOS): перевіряє .NET SDK (у `PATH` або `~/.dotnet`, тоді `PATH` і `DOTNET_ROOT` лише для свого процесу) і відповідність `server/global.json`, Node.js 23+, наявність рядка підключення (змінна середовища або `appsettings.Local.json`; з рядка беруться лише хост і порт, сам рядок не виводиться), доступність PostgreSQL (`pg_isready`, інакше `nc`), вільні порти 5080 і 5173 (називає процес, що їх тримає); за потреби робить `npm ci`.
- Запускає сервер (`dotnet run --launch-profile http`) і клієнт (`npm run dev --strictPort`) одночасно з префіксами `[server]` / `[client]`, чекає на `/health`, відкриває http://localhost:5173 (`--no-browser` вимикає). Ctrl+C зупиняє обидва дерева процесів (TERM, після 10 с KILL) і перевіряє, що порти вільні; якщо один процес упав, зупиняє другий.
- Повідомлення про помилки українською з підказкою «Як виправити».
- README: розділ «Швидкий старт: одна команда».

### Перевірка
- Прогін на цій машині: обидва процеси піднялися, `/health` через проксі Vite відповів `Healthy`, сторінка клієнта 200, при першому запуску сервер створив світ у `aetheris_dev` (3 сектори). SIGINT (як Ctrl+C) зупинив обидва процеси, порти вільні, у лозі немає пароля.
- Перевірено повідомлення про зайнятий порт і недоступну базу.

### Відхилення
- Під час прогону стандартні порти 5080 і 5173 тримали вже запущені сервер і Vite автора, тому перевірка йшла на 5180 / 5183. Для цього додано змінні `AETHERIS_SERVER_PORT` і `AETHERIS_CLIENT_PORT` (не було в задачі). Зауваження: на нестандартних портах вхід через браузер може впертися в перевірку `Origin` / CORS сервера (`Cors:AllowedOrigins`), бо дозволені адреси задані для 5173.
- Критерій 1 («у браузері відкривається») перевірено запитами `curl`, а не очима в браузері.

### Що лишилось
- Нічого в межах задачі; Windows/Linux і Docker поза задачею.
