# Задача 00029 — Повний огляд коду: пошук і виправлення помилок

> **Статус:** ✅ ВИКОНАНО 01.11.2026 (результат нижче; що агент не міг перевірити, у [00029-pytannia.md](00029-pytannia.md)).
> **Етап:** 1 (production/01)
> **Документи:** [tech/08 Правила коду](../tech/08-pravyla-kodu-dlia-ahentiv.md), [tech/09 Зведені правила](../tech/09-zvedeni-pravyla-kodu-lohiky-ta-kodiv.md)

## 1. Мета
Пройти весь код (сервер, клієнт, адмінка, тести, скрипти, CI), знайти помилки й **виправити їх усі**, а не лише описати.

## 2. Відома помилка (від автора)
Є шахта, але немає складу, а видобуток іде. Так бути не повинно: без складу видобуток не нараховується (точне правило звірити з game-design/02 і виправити за документом).

## 3. Що перевірити
1. **Видобуток і склад:** місткість складу, нарахування видобутку, межі, відсутній склад.
2. **Електростанції:** вироблення й споживання енергії, баланс планети, що буває при нестачі енергії, чи не нараховується зайве.
3. Решта коду: логіка, гонки й блокування, N+1, права доступу й власник об'єкта, транзакції, ізоляція модулів, хардкод, нестабільні тести, мертвий код, розбіжності документів і коду.
4. Червоні кроки CI на `main`: клієнтські тести складу, сканер секретів (2 хибні спрацювання gitleaks).

## 4. Критерії приймання
1. Відому помилку (п. 2) виправлено; є тест, який її відтворював і тепер проходить.
2. Електростанції перевірено, помилки виправлено, є тести.
3. Решту знайденого виправлено; список знайденого й виправленого з комітами в «Результаті виконання».
4. `dotnet build -c Release`, `dotnet test -c Release`, `dotnet format --verify-no-changes --no-restore`; у `client/` lint, test, build чисті; CI на `main` зелений.

## 5. Що не входить
Баланс і ціни (це [задача 00030](00030-zbalansovana-ekonomika.md)), нові механіки.

## 6. Результат виконання

**Знайдено й виправлено**

1. **Видобуток без складу** (помилка автора). Група ресурсів без місткості вважалася необмеженою (рішення 7.9 задачі 00020), тому шахта без складу нараховувала ресурси. Тепер група без складу не має місця: `PlanetEconomy.Accumulate` нічого не додає, у відповіді тіла швидкість такої групи нульова, заводи (`ProductionQueueService.HasRoomAsync`) нічого не виробляють у неї. Ресурс без складу не вважається «повним». Підказка в клієнті (`planet.storageNoCapacityHint`, uk і en) тепер каже, що видобуток не нараховується. Тести: `PlanetEconomyTests` (+2: ресурс без місткості, шахта без складу), `StorageCapacityTests` (+1: шахта без складу на тілі, після першого складу працює).
2. **Місткість у тоннах у виробництві.** `HasRoomAsync` порівнювала кількість штук з місткістю в тоннах (задача 00027). Тепер перевіряється вага: `(кількість + вихід) × вага ≤ місткість`.
3. **Електростанції.** Перевірено вироблення й баланс (`PlanetEconomy.Energy`, правило черги). Знайдено помилку: скасування запису черги, що дає енергію (електростанція), коли пізніші записи споживачів на неї спираються, лишало баланс тіла від'ємним. Тепер таке скасування відхиляється помилкою `planets_energy_short`, спочатку можна скасувати споживача. Тест: `ConstructionTests` (продовження сценарію черги: скасування електростанції під споживачем відхилено, потім дозволено).
4. **Блокування балансів у купівлі на ринку.** Покупка списувала баланс покупця, а потім нараховувала продавцю: два гравці, що купують один в одного одночасно, могли взаємно заблокуватися. Тепер баланси блокуються в порядку ідентифікаторів гравців.
5. **N+1.** `GetBuildingLevelsAsync` читав факти кожного тіла окремо (5 запитів на тіло); тепер одне читання власних тіл світу (`OwnedPlanet.Name`). `LimitAsync` ринку читав будівлі по одному тілу; нове `IPlanetsModule.GetBuildingEffectTotalsAsync` читає всі тіла одним запитом.
6. **Клієнт, CI.** 48 клієнтських тестів були застарілими після вирівнювання екранів за макетами (вільні місця черги, назви блоків, колонки складу, картка технології, відсутні кнопки); тести приведено до поточних екранів, усі 344 зелені. Тест блокування адреси (`SignInTests`) залежав від невдалих входів інших тестів з тієї ж адреси: тепер очищає лічильник на початку. Сканер секретів: два документи-приклади у виключеннях `.gitleaks.toml`.
7. Тести, що покладалися на старе правило (дослідження, оплата з виробленого): склад додано в підготовку (`ResearchTests`).

**Перевірки**

- Сервер: `dotnet build -c Release` без попереджень; `dotnet test` (виконуваний файл тестів, SDK 10.0.402 у пісочниці немає): 476 тестів, 475 зелених, один був нестабільним (`SignInTests`), виправлений і пройшов окремо (5/5). Повторного повного прогону після цього виправлення не було.
- `dotnet format --verify-no-changes --no-restore`: чисто.
- Клієнт: `oxlint` чисто, `vitest` 344/344, `npm run build` успішний.
- CI: клієнтське завдання зелене на коміті 6f077fc; результат сервера й сканера секретів після останнього коміту див. у `00029-pytannia.md`.
