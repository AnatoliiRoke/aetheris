# Задача 00070 — Сценарій бою і звіт бою в клієнті

> **Статус:** чернетка (чекає погодження автора)
> **Запит автора (12.11.2026):** задачі боїв з узгодженої логіки. Ця — сторінка сценарію флоту й перегляд звіту бою.
> **Логіка бою:** [game-design/06](../game-design/06-kosmichni-boi.md) §10, §11, [ui-art/03 §6–§7](../ui-art/03-interfeis-boiu.md).
> **Обов'язково прочитати:** `documentation/tech/08-pravyla-kodu-dlia-ahentiv.md`, `documentation/ui-art/05-yedynyi-styl-interfeisu.md`.
> **Залежить від:** макети [00068](00068-dyzain-ekrana-boiu.md), сервер [00066](00066-naslidky-boiu-remont-ulamky-zvit.md), [00067](00067-stsenarii-oborony-oflain.md), пошта [00060](00060-vnutrishnia-poshta.md).

## 1. Рішення

1. **Вкладка «Сценарій бою»** на сторінці флоту: бойовий порядок береться з вкладки «Формації» ([00071](00071-boiovyi-poriadok-flotu.md)), тут лише редактор правил «якщо → то» (рядки з випадаючих списків довідників, порядок перетягуванням), вибір шаблону, «Перевірити» (результат симуляції), «Зберегти».
2. **Звіт бою:** лист `combat_report` у пошті показує підсумок (втрати по проєктах, пошкоджені кораблі, уламки, переможець); кнопка «Переглянути бій» відкриває екран бою 00069 у режимі перегляду (цикли по черзі кнопками «◀ ▶»: позиції, сліди руху, журнал; без наказів).
3. Сторінки ліниві, оболонка не перемальовується; тексти в i18n; лише токени й готові компоненти.

## 2. Що зробити

1. API-клієнт сценарію; вкладка сценарію; режим перегляду в екрані бою; шаблон листа звіту.
2. Тести компонентів редактора правил і перегляду.
3. `npm run lint` і `npm run build` — зелені.

## 3. Критерії приймання

1. Усі елементи макетів сценарію й звіту з 00068 на місці.
2. Сценарій зберігається й застосовується в бою (перевірка разом з 00067).
3. Звіт відкриває перегляд бою.
4. Lint і build зелені.
