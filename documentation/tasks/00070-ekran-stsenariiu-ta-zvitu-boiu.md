# Задача 00070 — Сценарій бою і звіт бою в клієнті

> **Статус:** чернетка (чекає погодження автора)

> **Логіка бою:** [game-design/06](../game-design/06-kosmichni-boi.md) §10, §11, [ui-art/03 §6–§7](../ui-art/03-interfeis-boiu.md).

> **Залежить від:** макети [00068](00068-dyzain-ekrana-boiu.md), сервер [00066](00066-naslidky-boiu-remont-ulamky-zvit.md), [00067](00067-stsenarii-oborony-oflain.md), [00071](00071-boiovyi-poriadok-flotu.md), екран [00069](00069-ekran-boiu-v-kliienti.md), пошта [00060](00060-vnutrishnia-poshta.md).

## 1. Як є зараз (перевірено 13.11.2026)

Клієнт має пошту (`client/src/api/mailApi.ts`) і сторінки флотів; сценарію й перегляду бою немає. Вкладка «Формації» — задача 00071.

## 2. Рішення

1. **Вкладка «Сценарій бою»** сторінки флоту (`client/src/pages/fleets/ScenarioTab.tsx`, ліниво): бойовий порядок береться з «Формацій»; тут редактор правил «якщо → то»: рядок = `Select(умова)` + `Select(оператор)` + `Input(значення)` + `Select(дія)` + параметр дії (залежно від дії: вибір формації/ескадрильї/поведінки); порядок перетягуванням; «Додати правило»; ліміт `combat.scenario_rule_max` із відповіді API; шаблони (кнопка «Шаблон…» → список, застосування копіює правила); «Перевірити» (вибір суперника → результат); «Зберегти» (`PUT` з `expectedVersion`; `409` → «Сценарій змінено, оновити»).
2. **Звіт бою:** лист `combat_report` у пошті — компонент `CombatReportMail.tsx` за payload (00066 §4.5): переможець, цикли, втрати по проєктах (кількість і екіпаж), пошкоджені кораблі, уламки, втрати ворога (лише видиме); кнопка «Переглянути бій» → `/combat/:id?view=1`.
3. **Режим перегляду** у `CombatPage` (`?view=1`): без наказів і таймера, `CycleBrowser` `◀ ▶` по циклах `0…N` (`GET /combat/{id}/segments/{cycle}`), шари слідів, журнал; доступний лише учасникові (сервер перевіряє, дані відфільтровані за видимістю сторони).
4. Сторінки ліниві, оболонка не перемальовується; тексти — `client/src/texts`; лише токени й компоненти ui-art/05.

## 3. Файли й контракти

- `client/src/api/scenarioApi.ts`: `getScenario(fleetId)`, `saveScenario(fleetId, rules, expectedVersion)`, `applyTemplate(fleetId, templateCode)`, `checkScenario(fleetId, opponent)` → типи з 00067 §4.
- Довідники умов/дій/шаблонів — через наявний `contentApi` (нейтральні коди + назви з `localization_text`); у компонентах нейтральних кодів немає.
- `client/src/pages/fleets/scenario/{RuleRow.tsx,RuleList.tsx,TemplatePicker.tsx,CheckPanel.tsx}`.
- Валідація на клієнті дзеркалить сервер (значення в межах, `formationId` зі списку формацій цього флоту), але остаточна — серверна; помилки за кодами (`scenario_rule_invalid`, `scenario_rule_limit`, `scenario_conflict`).

## 4. Що зробити

1. API-клієнт сценарію; вкладка; `CombatReportMail`; режим перегляду.
2. Тести: `RuleRow` (залежний параметр дії), `RuleList` (порядок, ліміт), `TemplatePicker`, збереження з конфліктом, `CombatReportMail` з прикладу payload, `CycleBrowser` у режимі перегляду (без запитів на накази).
3. `npm run lint`, `npm run build`.

## 5. Критерії приймання

1. Усі елементи макетів сценарію й звіту з 00068 на місці.
2. Сценарій зберігається й діє в бою (перевірка разом з 00067).
3. Звіт відкриває перегляд бою; перегляд не дає змінювати нічого.
4. Lint і build зелені.
