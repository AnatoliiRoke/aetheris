## 1. Що робимо
1. **Сервер.** Захищений запит читання вмісту трюму флоту гравця (за інструкцією з README ядра «Як додати новий захищений запит»; лише власник флоту): перелік позицій `resource_id` / `amount` (підсумок флоту з `fleet_cargo`), місткість трюмів флоту і скільки зайнято (з `FleetHoldService`). Позиції з кількістю 0 не повертаються. Одним-двома запитами, `AsNoTracking`, без N+1. Якщо в трюмі з'являться деталі чи інші об'єкти (поки лише ресурси), контракт не заважатиме їх додати.
2. **Клієнт.** На картці/панелі флоту (сторінка «Флоти» і, де є, на карті) кнопка **«Показати трюм»**. Вона відкриває попап (наявний компонент діалога) з переліком: назва об'єкта (назва ресурсу з текстів сервера за `resource_id`, іконка ресурсу, якщо клієнт уже має компонент для іконки ресурсу) і кількість; угорі підсумок «зайнято / місткість». Порожній трюм: окремий текст «Трюм порожній». Дані читаються лише при відкритті попапа (не опитуванням по таймеру), попап не перемальовує решту сторінки.
3. Тексти українською й англійською в `uk.ts` / `en.ts`, стилі лише на токенах.

## 2. Критерії приймання
1. Кнопка «Показати трюм» є на флоті; попап показує всі ресурси трюму з кількістю (порядок: за кількістю спадно, потім за назвою) і підсумок зайнято/місткість.
2. Чужий флот: відмова, як в інших запитах флоту.
3. Порожній трюм і флот без кораблів: зрозумілий текст, без помилки.
4. Тести сервера (читання, чужий власник, порожній, кілька кораблів) і клієнта (кнопка, попап, порожній стан). Нові тести цієї задачі додавати можна.
5. Оптимізація: без N+1, читання лише при відкритті попапа, нуль хардкоду.
6. `dotnet build -c Release`, `dotnet test -c Release` (червоні тести, що були до задачі, перелічені в `00052-pytannia.md`, розділи 2.3 і 3; нових червоних немає), `dotnet format --verify-no-changes --no-restore`, у `client/` `npm run lint`, `npx tsc -b`, `npm run build`, `npx vitest run`.

## 3. Що не входить
Вивантаження і завантаження вантажу, передача між кораблями, перегляд трюму окремого корабля.

## 4. Рішення
1. **Контракт читання.** `GET /api/v1/fleet/fleets/{fleet_id}/hold` у групі читань модуля флоту (вхід гравця, ліміт `Command`; це читання без змін, тому без `Idempotency-Key`, за зразком інших читань `FleetEndpoints`). Відповідь `FleetHoldDto`: `fleet_id`, `capacity`, `carried`, `items[]` із `resource_id` і `amount`. Перелік `items` є місцем росту: інший об'єкт трюму додається як ще один вид позиції зі своїм посиланням, наявні читачі лише з ресурсами не ламаються.
2. **Власник.** Флот шукається за парою «флот + гравець із сесії»; чужий або неіснуючий флот дає `GameException(fleet_fleet_unknown)`, як у командах флоту (текст `reason.fleet_fleet_unknown` уже є).
3. **Джерела даних.** Місткість і зайнято: сума `ShipHold.Capacity` і `ShipHold.Carried` з `FleetHoldService.ReadAsync` (трюм корпусу плюс контейнерні модулі, вантаж `ship_cargo`). Позиції: рядки `fleet_cargo` флоту з `amount > 0`, `AsNoTracking`, порядок `amount` спадно, потім `resource_id` (клієнт ще раз сортує за назвою мовою гравця, бо сервер назв не бачить). Кількість запитів фіксована й не залежить від кількості кораблів чи ресурсів: перевірка власника, п'ять читань `FleetHoldService`, один запит позицій.
4. **Флот без кораблів** повертає місткість 0, зайнято 0 і порожній перелік, навіть якщо в `fleet_cargo` лишились старі рядки (трюмів немає, нести нічого).
5. **Клієнт.** Кнопка «Показати трюм» стоїть у блоці кнопок панелі флоту на сторінці «Флоти»; картка флоту є однією кнопкою вибору, тож вкладати кнопку в неї не можна. На карті панелі флоту немає (там лише відправка флоту), кнопки на ній немає. Кнопка й попап (`FleetHoldButton`/`FleetHoldDialog` у `fleets/FleetHold.tsx`) тримають стан відкриття в собі: відкриття й закриття перемальовують лише цей вузол, сторінка не чіпається. Попап створюється при відкритті й тоді ж читає трюм (`useRead` без повторного читання при поверненні на вкладку), опитування немає.
6. **Назви й іконки.** Назва ресурсу береться з пакета текстів сервера за `name_key` довідника ресурсів зі стану оболонки, іконка: `ResourceIcon` за кодом групи ресурсу з того ж довідника; клієнт не має таблиць «код → назва».
7. **Вікно.** Наявний `FleetDialog` (Esc, утримання фокуса, закриття хрестиком); окремої кнопки «Закрити» внизу немає, щоб не дублювати хрестик. Угорі підсумок «Зайнято X з Y т», порожній трюм: «Трюм порожній».
8. **Стилі** лише на токенах (`.fl-hold*` у `fleets.css`).
