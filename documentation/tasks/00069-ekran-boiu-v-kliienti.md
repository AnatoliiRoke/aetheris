# Задача 00069 — Екран бою в клієнті

> **Статус:** чернетка (чекає погодження автора)
> **Запит автора (12.11.2026):** задачі боїв з узгодженої логіки. Ця — перенесення макета екрана бою в клієнт.
> **Логіка бою:** [game-design/06](../game-design/06-kosmichni-boi.md), [ui-art/03](../ui-art/03-interfeis-boiu.md).
> **Обов'язково прочитати:** `documentation/tech/08-pravyla-kodu-dlia-ahentiv.md`, `documentation/ui-art/05-yedynyi-styl-interfeisu.md`.
> **Залежить від:** макет [00068](00068-dyzain-ekrana-boiu.md), API [00065](00065-tsykly-boiu-na-serveri.md).

## 1. Як є зараз

Екрана бою немає. Карта (PixiJS) і флоти на карті — задачі 00034, 00059.

## 2. Рішення

1. **Сторінка `/combat/:id`** (ліниве завантаження), вхід зі значка бою флоту на карті, зі сторінки флоту й зі списку «Мої бої». Оболонка (шапка, меню, футер) не перемальовується разом зі сторінкою.
2. **Поле — PixiJS:** камера (прокрутка, масштаб), об'єкти поля, зони розстановки, ескадрильї (значок групи, при наближенні кораблі), смуги щита/броні/корпусу, кола дальності, туман (маска), останні відомі позиції.
3. **Накази:** перетягування в зоні (розстановка), перемикач формацій флоту у фазі розстановки (кнопки-назви формацій, одне натискання застосовує формацію, поле одразу перераховується) і панель розподілу трюму (автоматичний розподіл, зміна кількості дронів і боєприпасів по кораблях у межах місткості), клік-точки маршруту (перетягування, видалення), панель наказу ескадрильї (поведінка, правило, фокус кліком по ворогу, дрони), поділ/об'єднання ескадрилей, «Готово», таймер фази.
4. **Результат циклу без анімації** (06 §3): з `GET /combat/{id}/segments/{cycle}` поле одразу показує нові позиції й стан; накази малюються статично (стрілки маршрутів, лінії до цілей фокусу, значки поведінки); перемикачі шарів «рух ворога» і «мій рух» (сліди від старої позиції до нової); позначки знищень; текстовий журнал поруч; перегляд попередніх циклів кнопками «◀ ▶».
5. **Оновлення:** зміна фази й новий відрізок приходять подією реального часу (00065); жодного опитування за таймером. Запит стану лише при вході й після події.
6. Тексти — i18n, кольори й розміри — лише токени `tokens.css` і готові компоненти; кольори сторін — токени.
7. **Продуктивність:** поле статичне — кадр малюється лише при зміні (накази, новий цикл, прокрутка, масштаб), постійного циклу малювання немає. 600 кораблів: прокрутка й масштаб плавні (≥50 кадрів/с на ПК з вбудованою графікою, ≥30 на бюджетному Android). Засоби: один атлас спрайтів і пакетне малювання (WebGL), рівень деталізації (у віддаленні ескадрилья — один значок), без фільтрів світіння на мобільних, роздільність полотна ≤ 2 на ПК і ≤ 1.5 на мобільних. Якщо WebGL недоступний — повідомлення замість поля.

## 3. Що зробити

1. API-клієнт `client/src/api/combatApi.ts` і типи.
2. Сторінка, сцена PixiJS, панель наказів, результат циклу й шари слідів, журнал, мобільна версія з макета.
3. Тести компонентів (наказ маршруту, фаза, «Готово»), тест побудови слідів і позицій з прикладу результату циклу.
4. `npm run lint` і `npm run build` у `client/` — зелені.

## 4. Критерії приймання

1. Усі елементи макета 00068 для екрана бою на місці.
2. Гравець проводить бій від розстановки до кінця лише через цей екран.
3. Немає опитування сервера за таймером; оболонка не перемальовується.
4. Вимоги продуктивності розділу 2.7 перевірено вбудованим лічильником кадрів (режим розробника) на сцені з 600 кораблями.
5. Lint і build зелені; ручна перевірка в Chrome — у `00069-pytannia.md`, якщо виконавець не може її зробити.
